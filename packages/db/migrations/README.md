# Migrations

Forward-only SQL, applied in journal order by `pnpm db:migrate` (PGlite or Postgres).
Generate table changes with `pnpm db:generate`; write views and other hand SQL with
`pnpm --filter @civic-ledger/db exec drizzle-kit generate --custom --name <name>`.
Never edit a migration after it has been applied anywhere; add a new one.

Each migration records how to undo it by hand if a release must be rolled back.

**Databases migrated on a feature branch.** `0006`-`0008` were renumbered when the district-map,
portrait and race branches were combined (2026-10-21). A database that ran the portraits or races
branch's own `0006` cannot be upgraded: drizzle skips every migration older than the last one applied,
and the renumbered file then fails (`type "portrait_variant" already exists`, `relation
"candidate_id_seq" already exists`). Recreate such a database (`pnpm db:migrate` on an empty one, then
ingest). A district-map branch database upgrades normally. Databases at `0005` or earlier are unaffected.
`0009_evidence_checks_provisional` was the evidence-trust branch's own `0006`, renumbered when it was
merged after `0006`-`0008` (2026-11-17). A database that ran that branch's `0006` has the same problem
(`relation "ingest_check" already exists`); recreate it the same way. Databases at `0008` upgrade normally.

| Migration | Change | Rollback note |
|---|---|---|
| `0000_init` | All fact, vocabulary and run-ledger tables, enums, natural-key constraints, FK indexes. | Empty database only: `DROP SCHEMA public CASCADE; CREATE SCHEMA public;` then re-run migrations. |
| `0001_person_card` | `person_card` and `person_card_scorecard` materialized views with sort/filter indexes. | `DROP MATERIALIZED VIEW person_card_scorecard; DROP MATERIALIZED VIEW person_card;` and delete the `0001` row from `drizzle.__drizzle_migrations`. No data loss (derived). |
| `0002_ingest_columns` | `rollcall.session` + `rollcall.clerk_number` (official clerk roll number; Voteview `rollnumber` stays in `number`) with a join index; `committee.organization_type` (FEC ORG_TP); `industry_coding_method` gains `fec_code`. | `DROP INDEX rollcall_clerk_idx; ALTER TABLE rollcall DROP COLUMN clerk_number, DROP COLUMN session; ALTER TABLE committee DROP COLUMN organization_type;` An enum value cannot be dropped in place: recreate the type without `fec_code` after deleting rows that use it. Delete the `0002` row from `drizzle.__drizzle_migrations`. |
| `0003_candidate_summary` | `candidate_cycle_summary` (FEC candidate summary: itemized / unitemized individual split, own coverage date) with natural key and person / provenance indexes. | `DROP TABLE candidate_cycle_summary;` after 0004 is rolled back; delete the `0003` row from `drizzle.__drizzle_migrations`. Data reloads from the next `fec-bulk` run. |
| `0004_person_card_scope_and_shares` | Rebuilds `person_card`: gross-based industry coverage, net-positive top industries, guarded receipt shares, small-dollar share from the candidate summary (`small_dollar_as_of`), `term_end` / `service_start` (+ index) for the current-member scope, `tenure_years` = years served. | Re-run the `CREATE MATERIALIZED VIEW person_card` block and its indexes from `0001_person_card.sql` after `DROP MATERIALIZED VIEW person_card;`, then refresh; delete the `0004` row from `drizzle.__drizzle_migrations`. No data loss (derived), but core ≥ this branch reads the new columns. |
| `0005_ingest_receipts_and_coverage` | `ingest_status` gains `cancelled`; `ingest_run.note`, `ingest_run.replay_of`; rebuilds `person_card` with a coalesced coded-coverage numerator (0, not null, when positive PAC money is all uncoded) and `refreshed_at = statement_timestamp()`. | `DROP MATERIALIZED VIEW person_card;` and re-run the `CREATE MATERIALIZED VIEW person_card` block and indexes from `0004`, then refresh; `ALTER TABLE ingest_run DROP COLUMN note, DROP COLUMN replay_of;` The `cancelled` enum value cannot be dropped in place (recreate the type after updating rows that use it). Delete the `0005` row from `drizzle.__drizzle_migrations`. Run with an app that predates 0005 only after rolling those back: older core cannot parse a `cancelled` receipt. |
| `0006_district_map` | `district_map`: precomputed locator-map SVG paths and viewBox per state outline (`district` null) and per numbered congressional district, with the Congress the district lines are for (`congress`, 119), vintage, publisher, as-of date and provenance; natural key `(state, district)` (nulls not distinct). Expand-only: nothing existing changes. | `DROP TABLE district_map;` and delete the `0006` row from `drizzle.__drizzle_migrations`. The map shapes are derived (reloaded by the next `census-boundaries` run, or by the dev seed). **What stays behind:** the `source` row `census-boundaries` and its `ingest_run` rows are not dropped (they are ledger facts; the `district_map` foreign keys went with the table). `/sources` and `sources.status` keep listing the source with its last run; delete them by hand (`DELETE FROM ingest_run WHERE source_id = 'census-boundaries'; DELETE FROM source WHERE id = 'census-boundaries';`) only if that is wanted. **Newer app on a rolled-back database:** profiles log `web.district_map` / `unavailable` and render without the map (the component fails soft); `/api/v1/districts.shape` and MCP `districts_shape` answer `internal`. **Older ingest or core builds:** their `SourceIdSchema` (`packages/core/src/contracts/ingest.ts`, parsed in `packages/ingest/src/runtime/ledger.ts` `toReceipt`) does not list `census-boundaries`, so asking such a build for a receipt of that source's rows throws; runs of other sources never read them. |
| `0007_person_portraits` | `person_portrait` (one validated JPEG per person and variant `225x275` / `450x550`: bytes (metadata stripped), content type, width, height, sha256 of the stored bytes, sha256 and size of the downloaded file, origin URL, provenance) with natural key `(person_id, variant)` (it also serves person lookups), provenance indexes and CHECKs (content type is `image/jpeg`, `octet_length(data) = byte_length`, sha256 is 64 lower-case hex); enum `portrait_variant`. Purely additive. | `DROP TABLE person_portrait; DROP TYPE portrait_variant;` and delete the `0007` row from `drizzle.__drizzle_migrations`. The `member-photos` row in `source` and its `ingest_run` receipts stay behind (they are ledger history; delete them only if the source is being retired, receipts first). Data reloads from the next `member-photos` run (the seed re-creates its synthetic images with `pnpm db:seed`). Older core ignores the table, so no reader breaks. |
| `0008_candidate` | `candidate`: every House and Senate candidate the FEC candidate master (`cn`) lists for an election year, as filed (name, party code, office, state, district, ICI, status, principal committee), natural key `(fec_candidate_id, cycle)`, nullable `person_id`, with seat / person / provenance indexes. | `DROP TABLE candidate;` and delete the `0008` row from `drizzle.__drizzle_migrations`. No other table references it; the data reloads from the next `fec-bulk` run (adapter `fec-bulk@3`). Races pages and `races.*` need the table, so roll back the app first. |
| `0009_evidence_checks_provisional` | `ingest_check` (successful unchanged rechecks, linked to the publication run they confirmed); `ingest_run.snapshot_locator` (immutable raw-evidence location); `ideology_score.provisional` (null = unknown). Additive only. | `DROP TABLE ingest_check; ALTER TABLE ingest_run DROP COLUMN snapshot_locator; ALTER TABLE ideology_score DROP COLUMN provisional;` and delete the `0009` row from `drizzle.__drizzle_migrations`. Loses recheck history and provisional flags (both recoverable by re-running ingest); older core ignores the new columns. |
